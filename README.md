# ML Service Practicum

Практическое задание №1: проектирование объектной модели ML-сервиса.

## Цель

Спроектировать основу личного кабинета ML-сервиса без реализации полноценного веб-приложения, базы данных, REST API, Telegram-бота и очередей сообщений.

## Основные сущности

- `User` — пользователь, данные для авторизации, роль и баланс.
- `Admin` — пользователь с возможностью пополнять баланс другим пользователям.
- `MLModel` — абстрактная ML-модель с описанием, стоимостью и методом предсказания.
- `ClassificationModel` и `RegressionModel` — конкретные виды моделей.
- `MLTask` — задача пользователя для выбранной модели.
- `PredictionResult` — результат предсказания, ошибочные данные и сумма списанных кредитов.
- `Transaction` — базовая финансовая операция.
- `CreditTransaction` и `DebitTransaction` — пополнение и списание кредитов.

## ООП

### Инкапсуляция

Баланс и хеш пароля пользователя объявлены приватными полями: `__balance` и `__password_hash`. Баланс изменяется только через методы `top_up_balance()` и `charge_balance()`.

### Наследование

- `Admin` наследуется от `User`.
- `ClassificationModel` и `RegressionModel` наследуются от `MLModel`.
- `CreditTransaction` и `DebitTransaction` наследуются от `Transaction`.

### Полиморфизм

- Метод `predict()` переопределяется в конкретных ML-моделях.
- Метод `apply()` по-разному работает у операций пополнения и списания.

### Модификаторы доступа

В Python используются соглашения:

- `field` — public;
- `_field` — protected;
- `__field` — private.

Основная объектная модель находится в файле [`object_model.py`](object_model.py).
