# Практическое задание №1

## Проектирование объектной модели ML-сервиса

В файле [`object_model.py`](object_model.py) спроектирована объектная модель личного кабинета ML-сервиса по требованиям первого практического задания.

На этом этапе намеренно не реализованы база данных, REST API, Telegram-бот, RabbitMQ, Web-интерфейс, Docker, мониторинг и тесты: они относятся к последующим заданиям курса.

## Основные сущности

| Класс | Ответственность |
|---|---|
| `User` | Данные пользователя, авторизация и история ML-запросов |
| `Balance` | Хранение суммы, проверка средств и история операций с балансом |
| `Admin` | Расширение пользователя: пополнение баланса других пользователей и просмотр всех транзакций |
| `MLModel` | Абстрактный интерфейс валидации, предсказания и расчёта стоимости |
| `BinaryClassificationModel` | Конкретный пример ML-модели, демонстрирующий наследование и полиморфизм |
| `MLTask` | Запуск ML-запроса, проверка баланса, валидация, предсказание и списание кредитов |
| `PredictionResult` | Предсказания по валидным данным, ошибочные строки и сумма списанных кредитов |
| `MLRequestHistory` | История ML-запросов пользователя |
| `Transaction` | Абстрактная транзакция баланса |
| `CreditTransaction` | Пополнение баланса |
| `DebitTransaction` | Списание средств после успешного предсказания |

## Покрытие требований

Модель поддерживает:

- регистрацию и авторизацию на уровне доменной сущности пользователя;
- роли пользователя и администратора;
- просмотр, пополнение и проверку положительного баланса;
- отправку данных в ML-модель;
- разделение входных данных на валидные и ошибочные;
- выполнение предсказаний только над валидными данными;
- списание кредитов только после успешного предсказания;
- хранение истории ML-запросов;
- хранение истории пополнений и списаний;
- связь транзакции списания с конкретной ML-задачей.

## Принципы ООП

### Инкапсуляция

Сумма и история операций находятся внутри отдельной сущности `Balance` и являются приватными полями. Пароль пользователя также хранится в приватном поле. Изменение баланса выполняется через методы класса `Balance`.

### Композиция

`User` содержит объект `Balance`, но не хранит сумму и историю транзакций самостоятельно. Управление балансом вынесено в отдельную ответственность.

### Наследование

- `Admin` наследуется от `User`;
- `BinaryClassificationModel` наследуется от `MLModel`;
- `CreditTransaction` и `DebitTransaction` наследуются от `Transaction`.

### Полиморфизм

- разные транзакции по-разному реализуют метод `apply()`;
- конкретные ML-модели могут по-разному реализовывать методы `validate_data()` и `predict()` через единый интерфейс `MLModel`.

## Модификаторы доступа

В коде используются соглашения Python:

- `field` — публичное поле;
- `_field` — защищённое поле;
- `__field` — приватное поле.

Поля, аргументы методов и возвращаемые значения снабжены аннотациями типов.

# Практическое задание №2

## Структура проекта и Docker Compose

В проект добавлена инфраструктура Docker Compose.

Созданы сервисы:

- `app`;
- `web-proxy`;
- `rabbitmq`;
- `database`.

Для сервиса `app` используется `env_file`, исходные файлы подключаются через `volumes`.

Для сервисов `rabbitmq` и `database` настроено хранение данных с использованием `volumes`.

Запуск проекта:

```bash
docker compose up
```
